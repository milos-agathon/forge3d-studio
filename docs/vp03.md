# VP-03 desktop viewport probe

Run from the Studio checkout with Node 24, the Windows Tauri build tools and a
working Forge3D Python engine with Rasterio. Set `FORGE3D_STUDIO_PYTHON`
or `PYTHONPATH` for that engine before running the probe.

```powershell
npm ci
node scripts/prepare-viewport-runtime.mjs
$scratch = Join-Path $env:TEMP "studio-vp03"
New-Item -ItemType Directory -Path $scratch -Force | Out-Null
$env:CARGO_TARGET_DIR = "$scratch/target"
$env:CARGO_PROFILE_DEV_DEBUG = '0'
$env:TAURI_CONFIG = '{"identifier":"dev.forge3d.studio.vp03","build":{"devUrl":"http://localhost:1426"}}'
cargo build --locked --manifest-path src-tauri/Cargo.toml
Remove-Item Env:TAURI_CONFIG
$vite = Start-Process node -ArgumentList 'node_modules/vite/bin/vite.js --host localhost --port 1427 --strictPort' -WindowStyle Hidden -PassThru
```

Run the probe with a new output directory and a free loopback CDP endpoint.
The driver launches and closes its own Studio processes with fresh WebView
profiles. Port 1426 is the startup gate and 1427 serves the checkout.

```powershell
node scripts/vp03.mjs --endpoint http://127.0.0.1:9456 --out "$scratch/run-01"
```

The driver picks up the debug binary from `CARGO_TARGET_DIR` or the checkout's
`target` directory. Use `FORGE3D_STUDIO_SHELL` or pass `--shell PATH` for an
explicit binary path. To pin a particular build artifact as well, pass
`--shell-sha256 HEX` using the SHA-256 from that build. Before Studio starts,
the probe reads the running shell's compiled native-source hash over Tauri IPC
and compares it to the current checkout. Cargo and the probe both use
`src-tauri/native-source.inputs` for the file set. The report retains the
executable digest and native-source hash. The source hash covers the Rust
crates, embedded Python, manifests and native resources listed there.

Pass `--historical PATH` to replay the saved VP-01 blocked-WebGL capture with
its existing comparator. Pass `--cog-fixture PATH` to exercise the
review's Bryce COG. Without it the driver creates a COG from the Bryce DEM
with a 500 m elevation offset, then serves it over loopback HTTP ranges.
Pass `--public-cog` to also probe and render the review's Copernicus tile over
HTTPS. The default probe tests the camera range boundary with local DEMs.

The driver holds Studio modules in the first document until it installs the
VP-01 context observer. It verifies HTML and offscreen canvases in the
document and in same- and cross-origin frames, plus offscreen canvases in
dedicated, shared and service workers. The blocked shell also launches with
WebGL disabled. The driver supplies file picker paths while the normal
Studio controls and native commands import, edit, delete, save and render.

The output includes visible WebView crops, transparent-clear terrain masks
and RGBA readbacks, saved projects and the native PNG and sidecar. The
five-state check compares compositor colors with GPU readback and derives the
active query's elevation, position and derivatives at the center and at a
second ground coordinate. It compares the accepted grid's Float32 bytes and
geometry against both the WASM upload and the dataset that answered the query.
For the five-state Bryce fixture, Import and Show also verify the selected
TIFF's file digest, its independently sampled 96 × 96 Float32 grid digest,
and both known interior elevations. The acquisition control substitutes a
real native preview of Bryce raised by 512 metres before the upload. It must
fail the source check even when the visible terrain relief is identical.
Controls substitute stale GPU heights and exaggeration, a retired dataset,
and stale heights in a fresh dataset whose two sampled points still match.
The probe checks the camera submitted to WASM against the live viewport pose
and injects an old camera after translating the terrain. Compositor checks
cover fractional canvas bounds at display scales 1.25, 1.5 and 2.5, and
opposite slopes with identical outlines. Native placement controls compare
Rendered and still export against the submitted Solid pose with translation
and positive uniform scale. The sidecar comparison allows floating-point
serialization precision. The wrong-size test retries a corrected sampler
response at the same resolution after hide/show.
The visibility control puts a hidden DEM first and compares the native still
with the visible DEM rendered on its own. It also checks that Rendered and
still export report an error when all terrain is hidden.

A separate blocked WebView holds a GPU buffer map while Bryce changes from
96 × 96 to 256 × 256. The probe compares the GPU height buffer and active
query with the accepted preview after successful upload, then injects a real
WASM validation failure. It also holds reads across hide, deletion, project replacement
and unmount, counting native creation and completed disposal independently of
the JavaScript facade and canvas context. A translated terrain that fails
camera validation must recover an empty frame on hide and on direct deletion.
A hidden 128 × 128 DEM before visible Bryce must yield a 1024 × 1024 MapScene
PNG when the user selects DEM size.

The File Close/Open checks hold an admitted-height read, a diagnostic read or a
native creation across viewport unmount. While the old native owner is live, a
new project can mount without acquiring a context. Once native disposal
finishes, the current host draws on its own canvas. The probe repeats all five
Bryce transitions there and checks native disposal before each new creation.
It also closes a waiting host before opening a third project.

The memory-budget checks exercise the runtime's own admission policy. At 2 MiB
the 256 × 256 Bryce request commits a 148 × 148 height texture. Studio reads
that texture, rebuilds the query and editor mesh from its samples, and reports
both sizes. The probe verifies the full GPU height buffer and eight ground
coordinates, including six vertices of the reduced grid. A tighter budget
exercises real synchronous and deferred rejection. Project replacement during
the admitted-height read also checks native retirement and the empty frame.

Gallery controls hold a reply across a URL edit and reject ranged PNG, RGB
TIFF, ungeoreferenced grayscale COG and all-nodata COG inputs. The probe
compares Float32 and scaled Int16 elevation through local Import and Gallery,
including overview reads and an explicitly foot-valued band on a metre CRS.
A survey-foot CRS fixture checks that physical geometry, slope and the camera
match the metre CRS fixture. The probe also
reopens a saved remote project with the HTTP source available and unavailable.
Legacy URL-backed projects without a saved footprint launch directly in
Rendered with WebGL denied, with and without an authored camera.

The JSON records actual WebView response and V8 script hashes, the pinned
archive inventory, project and terrain revisions, and runtime instance events.
Every first-party executable loaded from `/src/` in the primary WebView
document is verified against a separate local Vite compile. The comparison
normalizes Vite's optimized dependency cache paths and keys. The controls
alter both hillshade and a camera dependency with their original source maps.
Both must fail verification even when every upstream fetch returns the same
altered module.
