# VP-08 · Free-camera navigation

Run the desktop replay from the Studio worktree with its lockfile dependencies installed.

```powershell
node scripts/vp08.mjs
```

The driver uses the Windows WebView2, Rust and Python setup from VP-07. It locates Field Instrument at `64b7cf09` and verifies Studio’s vendored forge3d-web runtime at `d6459a26`. The candidate is based on VP-07 PR #11 at `55f94a32`. Each run prints the location of its full results.

## Startup and mouse input

Field used three.js with WebGL2. Studio used forge3d-web with WebGPU in a WebView launched with `--disable-webgl`. Both opened the relief-only Bryce DEM and cube at 794 × 727 CSS and physical pixels, DPR 1. Before any pose reset, both eyes were (9.5, 7, 11) and both targets were (3.487944, 3.076342, 4.038672). The first idle pixel-mode wheel event (deltaY = −100) changed radius from 10 to 9.5 and moved the eye 0.5 Studio units. Studio displayed one changed frame.

Both WebViews received the same 80 navigation events. The traces include viewport-relative coordinates, buttons, modifiers, wheel units and animation-update counts. The desktop mouse drove the drags and pixel-mode wheel events. The two line- and page-mode checks dispatched DOM wheel events. The replay compares live cameras after equal updates and independently compares the cameras used for the displayed frames.

From the explicit common target (0, 0.8, 0), a three-CSS-pixel left move shifted the eye 0.215581 Studio units after eight updates. Shift-, Ctrl- and Meta-right drags orbited about the fixed target. Right and modified-left pans kept target Y and radius fixed. The trace reached the lower hemisphere and both radius clamps, 0.8 and 150.

## Panning during orbit damping

The replay starts both cameras at (9.5, 7, 11) looking at (0, 0.8, 0). It repeats the same left orbit and right pan with either zero or one animation update between gestures. A third case sends two pan moves within one update interval while the orbit is still damping. Each case compares the live and displayed cameras at release and 260 updates later, then projects the five Bryce landmarks.

## Damping, picking and capture

After the early pan sample, Field and Studio each drew 36 frames over the next 100 updates and zero over the following 120. The four tested pan bindings matched the reference submission counts. Both 32-update idle windows also had zero submissions.

After orbit settled, a composited screenshot confirmed the magenta cube at physical pixel (400, 374). Clicking it selected Studio UUID `efcc1898-70bc-49d6-a20a-e534cabd1498` with one selection command. The navigation trace issued zero selection commands.

The driver sent another wheel event during orbit damping and pressed the World X grip before the next animation update. The live radius had changed from 15.671872 to 14.888279. The grip retained the displayed eye and target through the first held update, a wheel during capture, the 22 CSS pixel drag preview and release.

The independent review probe also replayed the wheel immediately followed by grip acquisition from radius 15.80158220. The displayed radius stayed at 15.80158220 on the first held update and the moved handle preview.

In a third WebView, hybrid rendering and the forced three.js fallback each applied the first wheel notch once. In both configurations, wheel input preserved the authored-camera and fly-mode poses.
