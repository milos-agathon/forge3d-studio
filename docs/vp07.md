# VP-07 · Move a cube along world X

From the Studio worktree with lockfile dependencies installed, run

```powershell
node scripts/vp07.mjs
```

The driver launches desktop WebView2 with `--disable-webgl`, verifies the vendored forge3d-web archive and browser assets at `d6459a26`, and uses Field Instrument `64b7cf09` for the transform-control replay. The worktree is based on the VP-06 merge `b08c31e2`, which has the same tree as the reviewed PR head `03b2cc4d`.

The driver also opens the parented fixture in a second WebView with the three.js editor available to compare the submitted cube centers. Each run prints its disposable evidence directory. For each supported fixture and mode it writes the selected native project before the drag, after release, and after reopening, alongside the saved `.studio3d`. The driver compares the complete before and after projects and allows changes only to the cube's X and the update timestamp. `results.json` contains the pointer events, capture state, submitted camera, framebuffer hashes, command counts and regression measurements.

## Regression checks

- **Immediate Save.** On original Bryce, delay the outgoing drag command and press Ctrl+S or Ctrl+Shift+S. Both wait for the edit, and the saved file reopens with the selected cube at the committed X. With the first acknowledgement held, Right, Right, Ctrl+S saves both nudges. A later edit remains dirty when a preceding Save is awaiting acknowledgement.
- **Consecutive drags.** Start a second 44-pixel drag on the displayed grip while the first acknowledgement is held. The driver acknowledges the first edit both during the next capture and after its release. Each moved drag adds one undo entry. Cancelling the second drag or releasing it without motion preserves the first edit.
- **Rotated parent at local X = 1000.** The driver measures the submitted world center after each of the nine moves under a 45° parent. It checks the stored and serialized displacements for both the drag and the subsequent keyboard nudge against the same world-axis tolerance.
- **Undo during capture.** Change native Y to 1.85, drag, then undo while delaying the native reply. Ctrl+Z and toolbar Undo release capture immediately and send zero transform requests on release. If native Undo runs outside the frontend, the session rejects the stale request under the project lock. All three cases preserve Y = 0.85 and the Redo that restores Y = 1.85.
- **Cancellation.** Escape, touch cancellation, capture loss, selection replacement, reopening the same project, and losing the displayed cube release capture. A late pointer-up and a zero-motion gesture add zero history entries.
- **Release before Undo.** Delay the outgoing transform after pointer-up, then press Ctrl+Z. Rust receives the X edit first. Undo restores (0, 1.85, 0), and Redo restores the X edit with Y still at 1.85. Activating the terrain row during capture releases the pointer before its delayed selection request is sent. The terrain becomes selected and the cube receives zero edits.
- **Edge and end-on views.** At cube X = 6 the visible shaft accepts the press at (760, 483). A second drag starts at viewport X = 766, keeps capture through X = 792 while the shaft is clipped, returns to X = 780 and commits one edit. Looking along X hides the axis when it projects to less than two pixels.
- **Native precision.** At X = 4,000,000,000, the 44-pixel gesture falls below one native translation step. The framebuffer stays fixed while held, and release sends zero commands.
  A cube and terrain both authored at X = 4,000,000,300 share the same submitted origin on X.
- **Hierarchy.** A cube under a parent rotated 90° about Z and scaled (2, 3, 1) moves along Studio world X. The child stores the corresponding local Y displacement. The GPU draw uses the same composed parent transform for preview and commit. A second parented fixture submits a center of (4.25, 0, 0) with the three.js editor available and with WebGL blocked. A rotated, zero-scale ancestor keeps its rendered geometry and exposes no X grip. At local X = 4 billion under a 45° parent, a one-unit nudge cannot survive native rounding along world X. The framebuffer and native transform stay fixed, with zero commands.
- **Keyboard.** Tab reaches the X button. Left and Right move 0.1 Studio units along world X. Shift increases the step to one unit. Enter or Space activates the button for a positive 0.1-unit step. With the first native acknowledgement held, two Right presses send two commands, add two undo entries and finish at X = 0.2.
