# VP-01 viewport verification

Capture Field Instrument and the viewport candidate in separate Studio launches.
Compare their saved masks and camera projections after both launches have closed.
The candidate's forced three.js run is an additional control. The original
single-endpoint diagnostic remains available for the standard dev server on
port 1420 as `node scripts/viewport-parity.mjs http://127.0.0.1:CDP_PORT`.

## Prepare the two Studio builds

Use Node 24, Git with the Studio history and sample assets, `tar`, and the Windows
Studio development prerequisites. Run the PowerShell commands from the VP-01
checkout and pick an unused scratch directory. The published Field (`9bad11c`)
and candidate (`55b6d78`) commits contain the viewport sources captured at
`64b7cf0` and `c3acc19`. The candidate carries the smaller Studio archive
with identical browser runtime files. The harness accepts the published
commits as source references in a fresh clone.

```powershell
$studio = (git rev-parse --show-toplevel)
$candidate = $studio
$vp = 'C:/tmp/forge3d-studio-vp01'
$field = "$vp/field-source"
$out = "$vp/results"
$fieldRevision = '9bad11c0cffca185e92f3f1120a65e1c47187216'
New-Item -ItemType Directory -Path $field, $out -Force | Out-Null
git -C $studio archive --format=tar -o "$vp/field-source.tar" $fieldRevision
tar -xf "$vp/field-source.tar" -C $field

Set-Location $field
npm ci
Set-Location $candidate
npm ci
node scripts/prepare-viewport-runtime.mjs
node scripts/vp01.mjs fixture --out "$out/fixture"

$env:CARGO_TARGET_DIR = "$vp/native-target"
$env:CARGO_PROFILE_DEV_DEBUG = '0'
$builds = @(
  @{name='field'; source=$field; port=1422},
  @{name='candidate'; source=$candidate; port=1423}
)
foreach ($build in $builds) {
  $env:TAURI_CONFIG = @{identifier="dev.forge3d.studio.vp01.$($build.name)"; build=@{devUrl="http://localhost:$($build.port)"}} | ConvertTo-Json -Compress
  cargo build --locked --manifest-path "$($build.source)/src-tauri/Cargo.toml"
  if ($LASTEXITCODE) { throw "Studio build failed" }
  Copy-Item "$env:CARGO_TARGET_DIR/debug/forge3d-studio-shell.exe" "$vp/$($build.name)-vp01.exe"
}
Remove-Item Env:TAURI_CONFIG

$fieldVite = Start-Process node -ArgumentList 'node_modules/vite/bin/vite.js --host localhost --port 1422 --strictPort' -WorkingDirectory $field -WindowStyle Hidden -PassThru
$candidateVite = Start-Process node -ArgumentList 'node_modules/vite/bin/vite.js --host localhost --port 1423 --strictPort' -WorkingDirectory $candidate -WindowStyle Hidden -PassThru
```

The recipe copies the Bryce DEM and NAIP imagery into a sibling `assets/`
directory. It keeps Bryce's camera and footprint and adds the two-unit cube
from `samples/cube-animation.studio3d` as `efcc1898-70bc-49d6-a20a-e534cabd1498`.
The cube uses RGB `[1, 0, 1]` at `[0, 0.85, 0]`. Material mode uses imagery
and the built-in sky. Project HDRI, hillshade, modelling grid, Sun shadows, and
Terrain sun shadows are off. The harness checks the loaded 96 × 96 preview and
4,000 × 3,800 footprint. Bryce's cartographic grid is retained.

The capture verifies each served viewport's source against its pinned Git
revision. It compares every prepared file under `/forge3d-web/` with the
vendored archive and records the file digests. Field's
runtime observer is inserted into one dev module response for that capture.
The candidate uses its existing development diagnostics. Both native builds
and browser profiles live in scratch locations.

## Capture and compare

Keep the windows at the same size and display scale. The driver opens the
fixture through the native Studio bridge and reloads the document so the
startup observer runs before application code. If a recovery banner takes
space above the viewport, the driver dismisses it through the UI and records
that action. Its saved snapshot stays on disk.

```powershell
function Capture-Vp01($role, $binary, $source, $cdpPort, $scale = $null) {
  $profile = "$vp/final-$role"
  New-Item -ItemType Directory -Path $profile | Out-Null
  $env:WEBVIEW2_USER_DATA_FOLDER = "$profile/webview"
  $env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS = "--remote-debugging-port=$cdpPort"
  if ($null -ne $scale) { $env:WEBVIEW2_ADDITIONAL_BROWSER_ARGUMENTS += " --force-device-scale-factor=$scale" }
  $process = Start-Process "$vp/$binary-vp01.exe" -WorkingDirectory $source -WindowStyle Hidden -PassThru
  try {
    $endpoint = "http://127.0.0.1:$cdpPort"
    $ready = $false
    for ($attempt = 0; $attempt -lt 50; $attempt++) {
      try {
        $ready = (Invoke-RestMethod "$endpoint/json/list" -TimeoutSec 1).title -contains 'Forge3D Studio'
      } catch { }
      if ($ready) { break }
      Start-Sleep -Milliseconds 200
    }
    if (!$ready) { throw "Studio CDP did not start for $role" }
    node scripts/vp01.mjs capture --endpoint $endpoint --role $role --fixture "$out/fixture/vp01-bryce.studio3d" --out "$out/$role"
    $captureExit = $LASTEXITCODE
    if ($role -eq 'webgl-blocked') {
      if ($captureExit -ne 1) { throw "Expected the WebGL-blocked capture to fail" }
    } elseif ($captureExit -ne 0) { throw "Capture failed for $role" }
  } finally {
    if (!$process.HasExited) {
      [void]$process.CloseMainWindow()
      if (!$process.WaitForExit(5000)) { throw "Close the verification Studio window for $role before continuing" }
    }
  }
}

Set-Location $candidate
Capture-Vp01 field field $field 9331
Capture-Vp01 candidate candidate $candidate 9332
Capture-Vp01 forced-three candidate $candidate 9333
Capture-Vp01 webgl-blocked candidate $candidate 9334

node scripts/vp01.mjs compare --field "$out/field" --candidate "$out/candidate" --out "$out/paired.json"
node scripts/vp01.mjs compare --field "$out/field" --candidate "$out/forced-three" --out "$out/forced-three.json"
node scripts/vp01.mjs controls --field "$out/field" --candidate "$out/candidate" --blocked "$out/webgl-blocked" --out "$out/controls"

npm test
npm run check
node --test scripts/vp01/*.test.mjs
```

An endpoint can be reused after closing its Studio launch. The comparison
requires different CDP targets for Field and the candidate. Captures write a
manifest even when they fail. At fractional or capped DPR the composited
PNG has its own physical dimensions. The harness maps drawing-buffer
pixel centres into that crop. A pair must still use matching drawing
buffers and camera poses. At 250% display scale, give both windows enough
CSS width for the candidate's View menu. The 250% verification used 1,200 × 460
CSS content pixels and drawing DPR 2.

The blocked run exits 1. Its control requires a real Studio WebGL denial,
an open fixture, the visible Studio WebGL error, and compositor evidence of an empty viewport at
the end of a bounded startup observation. The driver keeps the viewport
intact for 25 seconds from the first denial, the same budget used for
normal viewport readiness. It then saves the presented screen, replaces
canvas bitmaps while preserving decorative CSS, and suppresses image, video,
embedded media and CSS background images without changing layout. On
elements and generated `::before` and `::after` boxes, background colours
and gradients remain in place as image layers are removed. The probe
replaces generated content images with transparent images at the same
intrinsic size and checks that the box keeps its dimensions and paint.
The inventory includes fallback surfaces in the document, open shadow roots
and same-origin embedded documents. The screenshot crop limits the comparison to the
viewport. The offline control requires a complete presentation inventory,
the recorded timing and both frames. A third PNG, taken with the WebGL error
glyphs transparent, verifies that the error text painted inside the viewport
crop. The offline control remeasures that difference. An unfamiliar visible
viewport layer or a missing, clipped or occluded WebGL error makes the
blocked result inconclusive. Older startup captures replay with their
recorded probe. Verifying generated content with decorative CSS requires
a fresh capture with the current probe.
The driver installs the context guard in frames and pauses related worker
targets until their guards are installed. It records denial of all three
WebGL aliases and verifies WebGPU and 2D in the main document, a same-origin
iframe, and a dedicated worker.

The offline controls substitute two zero terrain masks and reuse the
candidate's measured hidden-cube mask as the visible mask in separate derived
captures. The latter must retain terrain parity while failing the object check.

Each live capture stores the stock viewport PNG before pass readbacks or
visibility probes. It then saves matched composited crops with the cube
hidden, and with the cube and terrain hidden. Offline comparison decodes
all three PNGs. The expected display contribution must appear in at least 90%
of each sample set, taken from the cube interior and the terrain outside it.
Terrain sampling excludes measured Studio toolbar and readout bounds, with
the total exclusion limited to 25% of candidate terrain samples.
The compositor-derived terrain silhouette must match the terrain readback
mask at IoU ≥ 0.97, including both missed and extra pixels. The comparator
also samples the stock PNGs at corresponding Field and candidate terrain
coordinates. Horizontal and vertical RGB differences must each have
cosine similarity ≥ 0.70 and at least half of Field's contrast. For colour
parity, at least 80% of shared terrain interior samples must agree within
24 levels in each RGB channel. The report records texture and colour checks
separately from the terrain readback IoU.
The default, low-oblique and near-nadir terrain-only probes also save
presented and no-terrain crops. The driver takes the presented crop before
the per-pose diagnostic readback. Each pose must independently pass the
display silhouette, Field texture and colour checks.
The selected click pixel must show the cube in the stock PNG. The Field
and candidate cube masks must have IoU ≥ 0.97, allowing the measured
antialiasing differences. Refresh older terrain captures for the per-pose
screens and older blocked captures for the generated paint inventory and error-text PNG.

The manifest names the masks. Each `.mask` has one byte
per physical drawing-buffer pixel, with 0 for background and 1 for coverage.
Rows and click pixels use the top-left origin. The trusted click targets the
physical pixel centre converted to CSS using the measured drawing-buffer
and CSS dimensions, accounting for rounding at the drawing DPR.
The manifest also records the window DPR, pointer event, three.js
raycaster call and resulting project selection.

The lower WebGPU terrain mask uses alpha from the shipped runtime readback.
Field and forced three.js use a transparent WebGL target containing the
Studio terrain mesh and the recorded camera. Terrain-only masks omit editor
objects and cartography. CPU landmark projection and raster silhouette
coverage are reported separately. The historical 16,091-pixel Field cube at
794 × 727 and DPR 1 is included for reproduction context.
