# VP-06 viewport click selection

From the Studio worktree with its lockfile dependencies installed, run

```powershell
node scripts/vp06.mjs
```

The driver uses the Windows WebView2, Tauri and Python environment used by VP-05. It verifies the vendored forge3d-web pin `d6459a26` and locates the Field Instrument worktree at `64b7cf09`. For the standalone example it reads the HTML directly from the pinned Git object in the sibling forge3d-web checkout. Set `FORGE3D_WEB_REPO` if that checkout is elsewhere. Each run prints a fresh output directory containing `clicks.csv` and the full `results.json`.

A separate desktop sweep compared 88 cube-only clicks at four camera distances with the framebuffer in Solid and Material. Every native selection and Scene Tree row matched. In the Bryce fixture, the picker also matched the isolated render at all 3,427 boundary pixels in each mode.

At an ambiguous WebGPU terrain or cube edge with a single candidate, Studio reads the submitted framebuffer's alpha to determine coverage. When both surfaces could own the pixel, including near-equal projected depths, Studio replays the submitted geometry and camera with the same depth attachment. Zero exposure makes terrain black, and a red emissive material identifies cube fragments. Clicks on the same submission share the resulting masks. At a terrain fold, a silhouette, or a steeply sloping cube face, Studio measures depth against the submitted terrain and cube together. It draws a small offscreen reference triangle at depths suggested by the projected faces. The GPU depth test narrows the range, including when the centre ray intersects a different face from the one covering the pixel. Studio restores the submitted batches, materials and lights, then unprojects the pixel centre at the measured depth. Repeat clicks on the same pixel and submitted frame reuse the measurement. Diagnostics that call the picker directly should use `await terrainViewport.pick(frame, pixel)` to include GPU readback.

When editor objects overlap at a pixel, three.js replays their draws with the displayed camera, draw order, depth precision and sample count. The ownership pass runs the original shader, then uses fixed-function blending to mark the samples contributed by each object. This preserves glTF OPAQUE materials with zero stored alpha, as well as alpha tests and transparency. The nearest object with surviving coverage wins. Within a depth tie the picker uses the object with the most coverage. This also handles an oblique face that is entirely behind terrain at the samples it covers. Selection boxes and the gizmo redraw on the editor canvas while the submitted picking frame stays available to pending clicks.

Viewport releases and Scene Tree clicks reserve their place in the same selection queue. A later tree replacement can take effect while a GPU read is pending. Later toggles are replayed in gesture order when that read completes.

Studio draws each editor mesh, line or point cloud into a scissored texel with its original materials and geometry. Each texel covers the clicked physical pixel. A single read checks up to 64 objects. This preserves the displayed float32 transforms, skin, morph weights, instances and sample coverage even when the pixel-centre ray misses the geometry.

The independent reassessment bundle repeated 128 skinned and rigid control clicks, 64 large- and local-coordinate clicks, and 72 decisive MSAA triangle clicks across Auto and forced three.js. All 264 matched the original framebuffer colours and expected IDs. Native selection and the selected Scene Tree rows agreed on every click.

The subsequent bundle checked 52 material clicks, 80 line and point clicks at large and local coordinates, and 64 clicks in scenes of 66 and 130 meshes. All 196 matched the supplied framebuffer samples, expected selection and Scene Tree rows. All eight orbit and click controls also produced the expected selection and native command count.

For a covered draw, Studio uses a clipping plane perpendicular to the view to check the depth of its nearest visible fragment. A matching ray intersection supplies the precise position. When the ray misses or disagrees with the draw, Studio narrows the clipping range and places the hit on the pixel-centre ray at the measured depth. Terrain hits use the grid UVs to recover raw DEM elevation, including on a flattened grid.

Line draws use the displayed physical stroke width. For a covered line or point cloud, the picker uses posed segments and point sprites near the pixel as depth hints. If large model coordinates shift the CPU projection away from the display position, the clipping query still recovers the displayed depth.

Inherited visibility now resolves each visited ancestor once per project snapshot. A 1,000-object chain measured 0.23 ms per snapshot on this host, down from 21.17 ms in the same benchmark before the fix. The regression test counts parent accesses on a reverse-ordered chain and checks visibility through a cycle.
