## From preview to screen

Studio accepts the north-to-south preview grid. `terrainInput` submits its Float32 samples to the renderer and builds the query dataset from the same input. Spacing on each axis is its ground span divided by the number of grid intervals. Vertex relief in metres is the accepted elevation minus the source datum. After centimetre rounding, a valid sample can lie below or above the source bounds. The material height range includes these samples so the shader preserves their signed relief. When both source bounds fall in one absolute Float32 bin, the sampler checks their centimetre bins. A single centimetre bin keeps the lower datum throughout. A centimetre boundary inside that Float32 bin preserves the clipped, unrounded block means. A constant texture gets a domain widened upwards.

For a non-flat DEM, Studio checks the errors in absolute Float32 elevation and signed relief at the maximum supported exaggeration of 50. If either exceeds 0.0001 untransformed Studio units at any vertex, the texture stores metres relative to the source datum. The dataset and renderer receive the same encoded heights and domain. Queries add the source offset to report metres of elevation. Grid reduction retains that offset. For each admitted texel, Studio recovers the corresponding accepted source elevation when it encodes to the GPU readback. The reduced editor mesh and its draped lines therefore retain the precision of the original preview. `terrainTransform` converts ground units to Studio units using `12 / max(groundSpanX, groundSpanZ)`, then applies the object's uniform scale and translation.

The viewport applies the inverse transform to the camera and incoming Studio ground queries. `ForgeTerrainViewport.queryTerrain` uses the dataset belonging to the visible submission. Studio calculates each world-space endpoint as `translation ± 6 × objectScale × side / longestSide`, rounding once after translation. Corner conversion and the inclusive query test share those endpoints. The viewport reuses them across frames with the same terrain and placement. The returned elevation uses the dataset’s bilinear sample. World Y interpolates the three signed vertex heights of the drawn triangle. Cartography and the editor mesh apply the source-datum conversion to their accepted vertices. The fallback cursor converts the three.js ray hit to mesh-local Y, then recovers elevation using the mesh’s datum and vertical scale. A constant DEM retains its exact source elevation after GPU grid reduction.

On the 12 × 6 m rounded-plateau fixture, the same pixel displayed **102 m** in both applications. On the 10 × 5 m fixture, the 101.5 m plateau has Float32 mesh Y 1.7999999523162842. Inverting the mesh’s 1.2 vertical scale gives 101.4999999603 m, and both applications displayed **101 m**. The probe compares the physical pixel, camera, DPR, viewport dimensions and cursor text.

The cartography line and label use metre ground spans and follow the terrain group's live transform. The line started directly above it at Y `4.459994`, including the scaled drape lift. The visible label landed at `(788.0, 194.5)` px against an expected `(787.9795, 194.4613)` px.

## VP-03 regression

The combined command exercises 52 VP-03 desktop checks, including the fractional capture. At startup the desktop harness waits for the probes on the packaged runtime before it releases Studio's entry module. It dismisses the asynchronous recovery banner through the UI so fixture names cannot change the viewport height between captures. The stale-query test compares both framebuffer dimensions and every RGBA byte.

The development proxy handles socket errors and closes the opposite side of an upgraded connection when either side disconnects. The loopback regression resets each end of a live upgrade and verifies that the next HTTP request succeeds.

The fractional capture derives expected domain and sample bytes from the accepted preview and its height origin. Its centre and off-centre Y values were 0.5999999866 and 1.1999999732. The expected upload, WASM input, GPU readback and queried datasets had the same SHA-256, `384ac152779a666340000bc2eadc91768a286582e35fa255be9ad934008779b8`. The original archived v4 project also passed. Its migration must produce exactly one visible relief layer. The settings check rejected the missing layer and a visible vector layer in its place. The retained-dataset control verified the matching centre query, identified the retired owner and rejected its stale off-centre elevation. The substituted-height control retained the current owner and used stale sample bytes, which the independent dataset digest detected.

The candidate passed `npm test`, `npm run check`, `npm run build` and all 20 VP-01/03 probe tests. The locked `studio-core` suite passed 163 tests with one ignored.
