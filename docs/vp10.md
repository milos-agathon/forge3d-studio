# VP-10 · World and local transform handles

Run the desktop replay from the VP-10 worktree with lockfile dependencies installed and the Field Instrument worktree available at `64b7cf09`.

```powershell
node scripts/vp10.mjs
```

The WebGPU scene uses the submitted pose and camera for the control. Studio projects the handle meshes into an SVG overlay and applies the full preview transform to the WebGPU scatter instance.

The command runs both desktop applications, prints the evidence directory and runs the VP-07 regression suite. Field Instrument at `64b7cf09` renders with WebGL2 and three.js 0.187.0. Studio starts with WebGL disabled and submits the cube through forge3d-web `d6459a26`. Both controls use size 0.85.

## Desktop comparison

The replay uses the pinned geometry to choose a pointer coordinate. It delivers trusted hover, press, move and release events to the Field WebView, waits for the drag frames, and reads the committed transform from Field’s native project. It then drives Studio at the same viewport-relative coordinates. The assertions compare the two event traces, native matrices, projected grips and held guides. After reopening, the replay waits for a WebGPU submission from the new project generation before reading its framebuffer. The archive contains the Field observations, Studio preview PNGs and framebuffer hashes, native command histories and regression reports. [Recorded desktop evidence](vp10-evidence.zip)

## Consecutive drags and parented planes

Two short sequences start with Global X Move. The second press acquires either center Move or Local Scale Y. Both desktop apps retain the selected UUID, camera, and open project between the two releases. The replay compares the native matrix and command count at each release, then undoes the second edit back to the first pose.

| Second grip on the same selection | Studio committed result | Maximum matrix error against Field |
| --- | --- | ---: |
| Center Move | Translation (1.0962474, 1.1886225, 0.0016812112) | 1.73 × 10⁻⁸ |
| Local Scale Y | Y scale 2.1215336 | 0 |

Two longer replays use physical toolbar clicks and twelve consecutive drags in each of Solid and Material. Each opens the project once and retains the selected cube through all twelve commits. Field picks each grip from the preceding committed pose and records the pointer coordinates. Studio replays those coordinates, including changes of direction, plane and center grips, the view and free-rotation grips, and scaling through zero. Each release checks the native matrix, selection, undo depth and command count. Run the longer sequences alone with `node scripts/vp10.mjs --sequences`.

The 41 isolated drags, four releases in the short sequences, and 24 releases in the longer sequences give 69 matrix comparisons. Each longer sequence advanced the native undo depth from zero to twelve. The worst matrix-element error was 1.40 × 10⁻⁷ in Solid and 3.05 × 10⁻⁶ in Material, below the 10⁻⁵ limit. During verification, one Field invocation timed out while loading terrain. The final standard replay recorded Field and Studio in the same run. All 70 Field recordings, including the separate large-coordinate regression, reproduced the earlier pointer coordinates and native matrices exactly. The final run recorded zero fixture retries.

The Solid sequence exposed two differences. Switching from Local Scale Y to Global Rotate Z left Studio using the previous scale plane for the press. Field had already reset the plane to face the camera. On the last Global Move Z, mouse-up arrived one pixel right and one pixel below the final move. Studio applied extra motion as it released. Field kept the last displayed pose. Studio now updates the control plane on toolbar changes and validates the release intersection while committing the held pose.

The tenth Material drag moves Local X with negative X and Y scales left by earlier edits. Field projects the pointer onto the decomposed world axes, then applies the authored rotation to the constrained displacement. Using the decomposed rotation in both directions reflected that displacement twice and sent the cube the opposite way. Studio now accounts for the scale signs when converting the constrained delta back to the displayed basis.

The first intersection uses the previously drawn drag plane. A toolbar change can retain that plane in Field. A center Move can therefore start at a different depth from its held screen plane. Each submitted Move preview advances the plane through the displayed pivot while preserving the original grab point. Studio checks the rounding error of the intended displacement at native float precision. For a local two-axis Move under a sheared parent, the normal comes from the cross product of the two displayed axes. The parent regression checks native motion along Local X and in Local XY and XZ, the framebuffer during capture, one transform on release and restoration on Undo.

The Local Scale Z pixel check compares idle and held desktop screenshots, sampling along the projected guide beyond the cube and ordinary grips. Both controls drew the guide at all 118 sampled locations. The evidence archive includes both idle and held screenshots from each desktop.

## Keyboard controls

Tab and Shift+Tab reach the visible grips. The focused controls show their grip names and arrow-key instructions. Left/right adjusts the first axis of a plane and up/down adjusts the second. The screen-plane Move grip and free-rotation grip use both arrow pairs in view space. Enter or Space applies one positive step. Shift multiplies the step by ten.

Move steps are 0.1 Studio units. Rotate steps are one degree. Scale applies a factor of 1.01 per positive step and its reciprocal per negative step, in local axes in both toolbar spaces. Each key adjustment uses the same sequence-checked command queue as pointer release. The replay uses Shift+Tab to reach all 38 grip-and-space combinations, applies an edit and undoes each one. A separate sequence focuses Local Y once and presses Left three times while the XZ grip becomes visible. It checks focus after every press and undoes all three commands.

## Desktop regressions

VP-07 derives expected X travel from the recorded pointer trace using the desktop acquisition order. On the original nine-move trace Studio stored X = 1.2628403 and the Field desktop app stored X = 1.2628404. The earlier 0.81615096 recording aligned the plane before recording the starting intersection. VP-07 covers pointer cancellation and late release, parent-local translation under a rotated nonuniform parent, singular ancestry, sub-float steps, keyboard nudges and edits spanning delayed acknowledgements. Its clipped-shaft case now starts at viewport X = 736. Field picks the Z cone at the historical X = 766. The regression verifies acquisition of X, carries capture through X = 792 and returns to X = 750 before release.
